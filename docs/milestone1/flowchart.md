# フローチャート設計

## 1. システム全体フロー

```
[システム起動]
    ↓
[設定読み込み]
    ↓
[データベース初期化]
    ↓
[スケジューラー起動]
    ↓
[Web管理画面起動]
    ↓
[メインループ開始]
    ├─→ [スケジュール更新タスク] (AM7:00-10:00)
    ├─→ [待機接客配信タスク] (60-90分間隔)
    └─→ [監視タスク] (常時実行)
```

## 2. スケジュール自動更新フロー

```
[スケジュール更新タスク開始]
    ↓
[現在時刻チェック] (AM7:00-10:00?)
    ├─→ No → [終了]
    └─→ Yes ↓
[アカウントリスト取得]
    ↓
[アカウントごとに並列処理]
    ├─→ [アカウント1処理]
    ├─→ [アカウント2処理]
    └─→ ...
    ↓
[アカウント処理フロー]
    ├─→ [セッション競合チェック]
    │   ├─→ 検知 → [スキップ] → [ログ記録]
    │   └─→ なし ↓
    ├─→ [ログイン確認]
    │   ├─→ 未ログイン → [ログイン処理]
    │   └─→ ログイン済み ↓
    ├─→ [URL自動判別]
    │   ├─→ doors1試行
    │   ├─→ 失敗 → doors2試行
    │   └─→ 成功 → URL記録
    ├─→ [週間スケジュール取得]
    ├─→ [出勤設定キャスト特定]
    ├─→ [翌日設定変更]
    ├─→ [登録実行]
    └─→ [ログ記録]
    ↓
[全アカウント処理完了]
    ↓
[結果サマリー生成]
    ↓
[終了]
```

## 3. 待機接客配信自動設定フロー

```
[待機接客配信タスク開始]
    ↓
[実行間隔チェック] (60-90分経過?)
    ├─→ No → [待機]
    └─→ Yes ↓
[アカウントリスト取得]
    ↓
[アカウントごとに並列処理]
    ↓
[アカウント処理フロー]
    ├─→ [セッション競合チェック]
    │   ├─→ 検知 → [スキップ] → [ログ記録]
    │   └─→ なし ↓
    ├─→ [ログイン確認]
    ├─→ [出勤キャスト数取得]
    ├─→ [人数制限チェック] (3人以下?)
    │   ├─→ Yes → [設定停止] → [ログ記録] → [終了]
    │   └─→ No ↓
    ├─→ [退勤時刻取得]
    ├─→ [時間制限チェック] (10分前超過?)
    │   ├─→ Yes → [時間調整]
    │   └─→ No ↓
    ├─→ [ステータス監視]
    │   ├─→ 「接客中」→「非更新エリア」検知
    │   └─→ 「待機中」に変更
    ├─→ [待機接客配信設定更新]
    └─→ [ログ記録]
    ↓
[全アカウント処理完了]
    ↓
[次回実行時刻設定] (60-90分後)
    ↓
[終了]
```

## 4. セッション競合検知フロー

```
[セッション監視開始]
    ↓
[定期的なチェック] (5秒間隔)
    ├─→ [Session Token取得]
    ├─→ [前回Tokenと比較]
    │   ├─→ 変化あり → [手動操作フラグ設定]
    │   └─→ 変化なし ↓
    ├─→ [DOM操作監視]
    │   ├─→ 自動操作以外の操作検知 → [手動操作フラグ設定]
    │   └─→ 検知なし ↓
    └─→ [ログイン状態確認]
        ├─→ ログアウト検知 → [再ログイン]
        └─→ 正常 ↓
[次のチェックへ]
```

## 5. アプリ停止検知と再起動フロー

```
[アプリ監視開始]
    ↓
[定期的な画面チェック] (10秒間隔)
    ├─→ [「赤い×」要素検索]
    │   ├─→ 検知 → [エラーログ記録]
    │   │   ↓
    │   ├─→ [ブラウザセッション終了]
    │   ├─→ [新しいブラウザセッション開始]
    │   ├─→ [ログイン処理]
    │   ├─→ [セッション状態復元]
    │   └─→ [処理再開]
    │
    └─→ 検知なし → [次のチェックへ]
```

## 6. ログイン処理フロー

```
[ログイン処理開始]
    ↓
[URL自動判別]
    ├─→ [アカウントに記録されたURL確認]
    │   ├─→ あり → [記録URL使用]
    │   └─→ なし ↓
    ├─→ [doors1試行]
    │   ├─→ 成功 → [URL記録] → [ログイン続行]
    │   └─→ 失敗 ↓
    └─→ [doors2試行]
        ├─→ 成功 → [URL記録] → [ログイン続行]
        └─→ 失敗 → [エラー] → [ログ記録]
    ↓
[ログインフォーム入力]
    ├─→ [ID入力]
    ├─→ [パスワード入力]
    └─→ [ログインボタンクリック]
    ↓
[ログイン成功確認]
    ├─→ 成功 → [セッション情報保存]
    └─→ 失敗 → [エラー] → [リトライ or 終了]
```

## 7. エラー処理フロー

```
[エラー発生]
    ↓
[エラータイプ判定]
    ├─→ [一時的エラー] (ネットワーク、タイムアウト等)
    │   ├─→ [リトライ] (最大3回)
    │   ├─→ 成功 → [処理継続]
    │   └─→ 失敗 → [エラーログ記録] → [通知]
    │
    ├─→ [致命的エラー] (認証失敗、アプリ停止等)
    │   ├─→ [エラーログ記録]
    │   ├─→ [通知送信]
    │   └─→ [該当アカウントスキップ]
    │
    └─→ [予期しないエラー]
        ├─→ [エラーログ記録] (スタックトレース含む)
        ├─→ [通知送信]
        └─→ [該当アカウントスキップ]
    ↓
[他アカウント処理継続]
```

## 8. Web管理画面フロー

```
[Web管理画面起動]
    ↓
[ログイン画面]
    ├─→ [認証]
    │   ├─→ 成功 → [ダッシュボード]
    │   └─→ 失敗 → [エラーメッセージ]
    ↓
[ダッシュボード]
    ├─→ [アカウント管理]
    │   ├─→ [一覧表示]
    │   ├─→ [追加]
    │   ├─→ [編集]
    │   └─→ [削除]
    │
    ├─→ [ログ閲覧]
    │   ├─→ [フィルタリング]
    │   └─→ [検索]
    │
    ├─→ [機能制御]
    │   ├─→ [スケジュール更新 ON/OFF]
    │   └─→ [待機接客配信 ON/OFF]
    │
    └─→ [監視画面]
        ├─→ [稼働状況]
        ├─→ [エラー一覧]
        └─→ [手動操作検知履歴]
```
