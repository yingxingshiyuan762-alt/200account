# 管理画面要件定義書

## 1. 管理画面の目的

- 200アカウントの一元管理
- システムの稼働状況監視
- ログの閲覧と分析
- 機能のON/OFF制御
- エラー状況の把握

## 2. 機能要件

### 2.1 アカウント管理機能

#### 2.1.1 アカウント一覧表示
- **表示項目**:
  - ID
  - パスワード（マスク表示）
  - 店名
  - ステータス（有効/無効）
  - 最終更新日時
  - ログインURL（doors1/doors2）
  - 最終ログイン日時
- **機能**:
  - ページネーション（1ページ20件）
  - 検索機能（ID、店名で検索）
  - ソート機能（各項目でソート可能）
  - フィルタ機能（ステータス、URLでフィルタ）

#### 2.1.2 アカウント追加
- **入力項目**:
  - ID（必須）
  - パスワード（必須、暗号化保存）
  - 店名（必須）
  - ステータス（有効/無効、デフォルト: 有効）
- **バリデーション**:
  - IDの重複チェック
  - パスワード強度チェック（オプション）
- **機能**:
  - 一括インポート（CSV形式）
  - 追加後の確認メッセージ

#### 2.1.3 アカウント編集
- **編集可能項目**:
  - パスワード
  - 店名
  - ステータス
- **機能**:
  - 一括編集（複数アカウント選択）
  - 編集履歴の記録

#### 2.1.4 アカウント削除
- **機能**:
  - 単一削除
  - 一括削除（複数アカウント選択）
  - 削除確認ダイアログ
  - 論理削除（物理削除はしない）

### 2.2 ログ閲覧機能

#### 2.2.1 ログ一覧表示
- **表示項目**:
  - 日時
  - アカウントID
  - 店名
  - ログレベル（INFO/WARNING/ERROR/CRITICAL）
  - メッセージ
  - エラー詳細（展開可能）
- **機能**:
  - リアルタイム更新（WebSocket）
  - ページネーション
  - 検索機能（アカウントID、店名、メッセージで検索）
  - フィルタ機能（ログレベル、日時範囲、アカウントでフィルタ）
  - エクスポート機能（CSV形式）

#### 2.2.2 ログ詳細表示
- **表示項目**:
  - ログの全情報
  - スタックトレース（エラーの場合）
  - 関連するスクリーンショット（エラーの場合）
  - コンテキスト情報

### 2.3 機能制御機能

#### 2.3.1 スケジュール自動更新のON/OFF
- **機能**:
  - 全体のON/OFF切り替え
  - アカウント単位のON/OFF切り替え
  - 実行時刻の設定（AM7:00-10:00）
  - 次回実行時刻の表示

#### 2.3.2 待機接客配信のON/OFF
- **機能**:
  - 全体のON/OFF切り替え
  - アカウント単位のON/OFF切り替え
  - 実行間隔の設定（60-90分）
  - 次回実行時刻の表示

#### 2.3.3 緊急停止機能
- **機能**:
  - 全処理の即座停止
  - 停止確認ダイアログ
  - 停止理由の記録

### 2.4 監視機能

#### 2.4.1 稼働状況表示
- **表示項目**:
  - システムステータス（稼働中/停止中）
  - 処理中アカウント数
  - 待機中アカウント数
  - エラー発生アカウント数
  - CPU使用率
  - メモリ使用率
  - 処理速度（アカウント/分）

#### 2.4.2 エラー一覧表示
- **表示項目**:
  - エラー発生時刻
  - アカウントID
  - 店名
  - エラータイプ
  - エラーメッセージ
  - ステータス（未対応/対応中/対応済み）
- **機能**:
  - エラーの詳細表示
  - エラーの対応状況更新
  - エラーの検索・フィルタ

#### 2.4.3 手動操作検知履歴
- **表示項目**:
  - 検知日時
  - アカウントID
  - 店名
  - 検知方法（Token変化/DOM操作）
  - 処理結果（スキップ/継続）
- **機能**:
  - 検知履歴の検索・フィルタ
  - 統計情報の表示（検知頻度など）

### 2.5 統計・レポート機能

#### 2.5.1 日次レポート
- **表示項目**:
  - 処理成功数
  - 処理失敗数
  - エラー発生数
  - 手動操作検知数
  - 平均処理時間

#### 2.5.2 週次レポート
- **表示項目**:
  - 週間統計
  - エラートレンド
  - パフォーマンス推移

#### 2.5.3 カスタムレポート
- **機能**:
  - 期間指定
  - 項目選択
  - エクスポート（CSV/PDF）

## 3. UI/UX要件

### 3.1 デザイン要件
- **レスポンシブデザイン**: PC、タブレット、スマートフォン対応
- **ダークモード**: オプションでダークモード対応
- **アクセシビリティ**: WCAG 2.1 AA準拠

### 3.2 画面構成

#### ダッシュボード
- システム全体の概要表示
- 主要メトリクスの表示
- クイックアクション

#### アカウント管理画面
- アカウント一覧
- アカウント追加/編集フォーム
- 一括操作パネル

#### ログ閲覧画面
- ログ一覧
- ログ詳細モーダル
- フィルタパネル

#### 監視画面
- リアルタイム監視ダッシュボード
- エラー一覧
- 手動操作検知履歴

#### 設定画面
- 機能制御
- システム設定
- 通知設定

### 3.3 操作性要件
- **直感的な操作**: 3クリック以内で主要機能にアクセス
- **確認ダイアログ**: 重要な操作には確認ダイアログ
- **フィードバック**: 操作結果の明確なフィードバック
- **エラーメッセージ**: 分かりやすいエラーメッセージ

## 4. セキュリティ要件

### 4.1 認証・認可
- **ログイン機能**: ユーザー名とパスワード
- **セッション管理**: セッションタイムアウト（30分）
- **権限管理**: 管理者/一般ユーザーの権限分離（将来拡張）

### 4.2 データ保護
- **パスワード暗号化**: データベースに保存するパスワードは暗号化
- **通信の暗号化**: HTTPS必須
- **ログの機密情報マスキング**: パスワードなどの機密情報はログに記録しない

## 5. パフォーマンス要件

### 5.1 レスポンス時間
- **ページ読み込み**: 2秒以内
- **検索・フィルタ**: 1秒以内
- **データ更新**: リアルタイム（WebSocket）

### 5.2 同時接続数
- **最大同時接続数**: 10ユーザー

## 6. 技術要件

### 6.1 フロントエンド
- **フレームワーク**: Flask（サーバーサイドレンダリング）または React（将来拡張）
- **UIライブラリ**: Bootstrap 5 または Tailwind CSS
- **リアルタイム通信**: WebSocket（Flask-SocketIO）

### 6.2 バックエンド
- **フレームワーク**: Flask
- **データベース**: SQLite（開発）/ PostgreSQL（本番推奨）
- **ORM**: SQLAlchemy

### 6.3 API設計
- **RESTful API**: 将来の拡張性を考慮
- **エンドポイント**:
  - `/api/accounts` - アカウント管理
  - `/api/logs` - ログ取得
  - `/api/monitoring` - 監視データ取得
  - `/api/control` - 機能制御

## 8. データモデル

### 8.1 アカウントテーブル
```sql
CREATE TABLE accounts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    account_id VARCHAR(255) UNIQUE NOT NULL,
    password_encrypted TEXT NOT NULL,
    store_name VARCHAR(255) NOT NULL,
    login_url VARCHAR(255),
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 8.2 ログテーブル
```sql
CREATE TABLE logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    account_id VARCHAR(255),
    store_name VARCHAR(255),
    level VARCHAR(20) NOT NULL,
    message TEXT NOT NULL,
    details TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 8.3 エラーログテーブル
```sql
CREATE TABLE error_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    account_id VARCHAR(255),
    error_type VARCHAR(50) NOT NULL,
    error_code VARCHAR(50),
    message TEXT NOT NULL,
    stack_trace TEXT,
    status VARCHAR(20) DEFAULT 'UNRESOLVED',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    resolved_at TIMESTAMP
);
```

## 9. 実装優先順位

### Phase 1（必須機能）
1. アカウント管理（追加・編集・削除・一覧）
2. ログ閲覧（一覧・詳細）
3. 機能制御（ON/OFF切り替え）
4. 基本的な監視（稼働状況表示）

### Phase 2（重要機能）
1. エラー一覧
2. 手動操作検知履歴
3. 統計・レポート
4. リアルタイム更新

### Phase 3（拡張機能）
1. 一括操作
2. カスタムレポート
3. エクスポート機能
4. ダークモード
